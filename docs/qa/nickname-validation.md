# 닉네임 검증 QA

## 규칙

새 닉네임 제출에만 2–10자 완성형 한글·ASCII 영문·숫자 규칙을 적용한다.
공백 제거·문자 치환 없이 원문을 검증한다. 기존 닉네임 표시와 중복확인 API의 최대 64자 조회 계약은 유지한다.

## 로컬 검증

- 실행: `npm run test:unit`, `npm run test:nickname-browser`, `npm run build`
- 브라우저 검증에는 Playwright Chromium이 필요하다 (`npx playwright install chromium`).
- `test:nickname-browser`는 실제 가입 2단계 컴포넌트·가입 훅·닉네임 변경 페이지를 Chromium에서 실행한다.
- 전화·소셜 인증 진입 단계는 제외하고 API 응답을 모의한다. 실제 서버에 가입·변경 요청을 보내지 않는다.
- 테스트용 화면 파일은 실행 중 임시 생성하고 종료 시 삭제한다.

## QA 환경에서 남은 확인

로컬 모의 API 검증으로 아래 항목을 완료 처리하지 않는다.

- [ ] 닉네임 변경분이 반영된 QA 배포 버전 확인
- [ ] 일반 가입: 전화 인증부터 가입 완료까지 실제 서버 연동 확인
- [ ] 소셜 가입: 소셜 인증부터 가입 완료까지 실제 서버 연동 확인
- [ ] 닉네임 변경: 실제 중복 응답과 저장 성공, 재조회 결과 확인
- [ ] 기존 장문·특수문자 닉네임 계정의 마이페이지·변경 화면 표시 확인
- [ ] 기존 닉네임의 최대 64자 중복조회 계약 유지 확인

`fix/nickname-validation` 브랜치에서 `dev` 대상 Draft PR과 Vercel Preview 배포를 준비한다. Preview 반영 확인과 실제 서버 연동 QA는 구분해 기록한다.
